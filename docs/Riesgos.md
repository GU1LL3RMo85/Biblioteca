# Riesgos

Riesgo 1: Cambios constantes en los requisitos del cliente (Scope Creep)
Existe una alta probabilidad de que la biblioteca solicite nuevas funcionalidades no planificadas durante el desarrollo (por ejemplo, agregar más tipos de usuarios o reglas de multas complejas). Esto puede retrasar el cronograma de entregas.

Riesgo 2: Inconsistencia por concurrencia de datos
Si dos estudiantes intentan reservar el último ejemplar disponible de un libro en el mismo milisegundo, el sistema podría registrar ambas reservas y generar un conflicto físico en la biblioteca si la base de datos no maneja correctamente las transacciones.

Riesgo 3: Resistencia al cambio tecnológica por parte del personal
Los bibliotecarios y el personal administrativo podrían mostrar resistencia a utilizar el nuevo sistema si la interfaz gráfica no es intuitiva, lo que retrasaría la adopción del software y requeriría horas extra de capacitación.

Riesgo 4: Vulnerabilidad en la protección de datos personales
Al almacenar historiales de préstamos, matrículas y datos de contacto de estudiantes y profesores, el sistema está expuesto a accesos no autorizados si no se implementan protocolos básicos de seguridad y encriptación en las contraseñas.
